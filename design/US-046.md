# US-046 · Darken layers and backgrounds for contrast

## Approach
- **Schema.** `dim: boolean` (optional, off) on `TileLayer` and `Background`; `dimLevel: 0..16` (optional, 0) on `Room`. All are optional, so old files load unchanged.
- **Hardware.** The GBA brightness-decrease effect: BLDCNT mode "darken" with the dimmed layers as first target, BLDY = level (0 to 16). agb 0.25 has `Blend::darken()` with per-layer targets (`display/blend.rs`), so no raw register code. Sprites are not a target, so they stay bright. It uses no palette slots, tiles or CPU. The alpha blend is not touched, so a later fade/blend story can share `Blend` (the dim code lives in one `dim` module in `runtime/src/gfx.rs` or a new `gfx/dim.rs`).
- **Data section.** The room record is full (64 bytes), so the dim settings go in free bits of `R_FLAGS` (u16): bits 2-4 tile layers 0-2 dimmed, bits 5-6 backgrounds 0-1 dimmed, bits 8-12 level. Old data has zeros there, so it means "no dim". No stride change, so `layout.rs` `VERSION` stays 1. Alternative, growing the record to 68 bytes, would force a layout version bump and break ROM patching of existing ROMs.
- **Pure logic in `runtime/src/data` (no deps, host-testable).** `Room::dim_level()`, `Room::dim_layers()` (mask), and a `Dim` helper: current level, target, frames left, `set(level)`, `fade(level, frames)`, `step()`, `reset_to(room)`. `gfx` maps the mask onto the BG layers that are actually used (tile layer n and background n get different hardware layers depending on priority) and calls `Blend::darken`.
- **Runtime API.** `set_dim(level)`, `fade_dim(level, frames)`, called once per frame via the existing view update. On room change, the level is reset to the room's own.
- **Preview.** One function in `core` (`dimColour(rgb555, level)`) with the hardware rounding: `c - floor(c * level / 16)` per 5-bit channel. Map editor and Play preview apply it to dimmed layers only.
- **Validation (`core/src/validate.ts`).** Level 0 with a dimmed layer: "layer X is set to dim, but the room's dim level is 0, so nothing is darkened". Level above 0 and no dimmed layer: "no layer is dimmed, so the level does nothing". `dimLevel` above 16 is a schema error. Mirrored in codegen's problem list.
- **UI.** Room panel: a toggle per layer row and one slider (0 to 16); the layer list shows a "dimmed" tag. A note says the level is shared by all dimmed layers.
- **MCP.** Extend the room tools in `server/src/tools.ts` with `dim` on layers and backgrounds and `dimLevel`; they answer with the problems left. No writes under `assets/`.
- **Docs.** `rooms.md`, `project-format.md`, `data-section.md` (flag bits), `agents.md` tools list, `limits.md` (one level for all dimmed layers), a screenshot entry in `docs/screenshots.json`.

## Format changes
- `core/src/schema.ts`: `dim` on `TileLayer`, `Background`; `dimLevel` on `Room`.
- `codegen/src/model.rs`: the same, `#[serde(default)]`.
- Data section: flag bits in `R_FLAGS` (see above), `core/src/datasection.ts` writer and reader, `runtime/src/data/write.rs`, `docs/reference/data-section.md`.
- `FORMAT_VERSION` stays 1 (old projects load unchanged). Data section `VERSION` stays 1.

## Hardware cost
- ROM: a few dozen bytes of code. Data: none extra (flag bits).
- IWRAM/EWRAM: one small `Dim` struct (about 8 bytes).
- VRAM and palettes: none. CPU: one BLDY write per frame at most (only while fading).
- Estimated; checked by building `sample/` and reading the headless emulator frames.

## Tests
1. Per-layer `dim`, others and sprites untouched: vitest `core` (schema, preview only dims flagged layers); Rust host test for the layer mask; headless frame of the sample with a sprite over a dimmed layer.
2. `dimLevel` 0 to 16, hardware effect: schema vitest (rejects 17); `runtime` host test of the BLDCNT/BLDY values per level and layer set (pure function returning the register values).
3. `set_dim` and fade, reset on room change: `runtime/src/data` host tests of `Dim` (fade steps, ends exactly at target, reset).
4. Preview rounding: vitest on `dimColour` against the shared fixture.
5. Room panel toggle, slider and list tag: no automated test in the app today; checked by hand and with the screenshot.
6. MCP tools: `server/test` tests for setting `dim`/`dimLevel`, returned problems, and that nothing under `assets/` is written.
7. Validation problems: `core/test` for both cases, with the message wording.
8. Old projects: a test loading a room without the fields; the data-section round trip of an old room.
9. Fixture: `codegen/fixture/dim.json` (colours by level) read by a Rust test in `runtime` and a vitest in `core`.
