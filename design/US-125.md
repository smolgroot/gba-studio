# US-125 · Ctrl+W closes the document, not the project

## Approach
The desktop app's File menu owns the shortcuts, because a menu accelerator works
whichever view has focus (the tab bar or the project page). So:

- **Main process.** The File menu gets *Close Document* (`CmdOrCtrl+W`) and
  *Close Project* (`CmdOrCtrl+Shift+W`). The template moves out of `main.ts` into
  `desktop/src/menu.ts`, which takes the actions as plain functions and imports
  only Electron's types, so it can be tested without Electron. *Close Document*
  calls `Projects.closeDocument()`, which sends `close-document` to the active
  project's page if it has one; a starting or failed project has no page, so
  nothing happens.
- **Page bridge.** `page-preload.ts` gains `onCloseDocument(listener)`, which
  returns a function that stops listening. `PageBridge` in `protocol.ts` says so.
- **Page.** `DockLayout` listens through the bridge when it is there. Which tab to
  close is decided by `documentToClose()` in a new `app/src/doctabs.ts`:
  the active panel if it is a document tab, otherwise the document tab of the
  current selection (the one in front, when focus is in Project or Properties),
  otherwise nothing. The tab closes through its own `api.close()`, as its × does.
- **Browser.** Nothing listens for Ctrl+W in the page itself, only the bridge, so
  in a browser the browser keeps the key. The narrow one-panel layout has no
  document tabs and does not listen, so Ctrl+W does nothing there.

Alternatives considered:
- A `keydown` handler in the page: it does not see the key while the tab bar has
  focus, and the menu accelerator would still close the project.
- `executeJavaScript` from the main process, as the save flush does: it works, but
  a named message through the preload keeps the page's surface small and typed.

## Hardware cost
None: studio only.

## Tests
- Close Document is `CmdOrCtrl+W` and Close Project `CmdOrCtrl+Shift+W` in the
  File menu, and each calls its own action: `desktop/test/menu.test.ts`.
- The active document tab closes; with focus in another panel, the selection's tab
  closes; with no document tab open, nothing does: `app/test/doctabs.test.ts`.
- The browser is unchanged: the page only reacts through the desktop bridge (checked
  in the review of `App.tsx`; there is no `keydown` handler for `w`).
- Docs: `docs/reference/shortcuts.md` and `docs/guide/desktop.md`.
