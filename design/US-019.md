# US-019 · An Entities page for entity types, their properties and behaviours

## Approach

A new selection kind, `entities`, with the type id as its `id` (`#entities:sentry`),
edits `studio/project.json` as Physics does: `editedDoc` maps it to `project`, so undo,
redo and the "Not undone" notice work unchanged. The page lives in a new
`app/src/panels/entities.tsx`; `panels.tsx` (760 lines) loses the entity table and
gains a sidebar section and a `case`.

**Sidebar.** `SECTIONS` gains `Entity types` after `Sprites`: one row per type
(colour square, name, `typeSummary` as detail), selected when the Entities page shows
that type, and an add button that adds a type and opens it. The activity bar gets the
section's icon (`CategoryOutlined`) with the count, and `kinds: ['entities']` so it
lights up on the page. There is no separate top item: the section is the way in, as
it is for Rooms.

**The page** is two columns, as the Tools page is:

- *Left, the list* (about 260 px, scrolls on its own): **Add entity type** at the top,
  then a `listbox` of rows. A row: the sprite's first frame drawn at 2× in a 32 px box
  (the colour square when the type has no sprite or it is not a PNG, as `EntityMarker`
  draws on the map), the name, `typeSummary`, and the number placed, with a dot in the
  type's colour. Up and Down move the selection, Home and End jump, Enter and Space
  select (the selection already follows the arrow keys, so these only confirm).
- *Right, the type*: a header with the sprite preview (first frame at the largest whole
  scale that fits 96 px; the colour square when none) beside the name, colour and sprite
  fields and **Delete entity type**. Under it **Properties** (`TypeProperties`) and
  **Behaviours** (`TypeBehaviours`) in a CSS grid of `repeat(auto-fit, minmax(420px,
  1fr))`, so they are side by side on a wide page and stacked on a narrow one. Under
  them **Placed in**: a row per room that places the type, with its count, as a button
  that opens the room; "Not placed in any room yet." otherwise.
- With no types, the right side says what an entity type is (the text now under the
  table) with **Add entity type**.

`#entities` with no id, or an id that is not a type, shows the first type; the address
is not rewritten, so going back still works.

**Usage.** `core/src/entities.ts` (new): `typeUsage(rooms, typeId)` →
`{ room, roomName, count }[]` in room order, and `withoutType(project, typeId)`. Pure,
so the counts on the list, the "Placed in" list and the delete question all come from
one function, tested in vitest.

**Delete.** A type with no placed entities is removed at once (one undo step, as
today). One that is placed asks with `window.confirm` — the same as deleting a room
does — "Delete the entity type “Sentry bot”? 3 entities in 2 rooms (Entry, Shaft) use
it; they stay in the rooms and show as problems until they get another type." It
does not change rooms: what to do with orphaned entities is the open question in the
story and stays out of this one. After a delete the page shows the type above it, or
the next one.

**Links in.**
- Room panel, a placed entity's **Type** field: an icon button beside the select,
  "Open Sentry bot on the Entities page".
- Problems: `selectionForProblem(problem)` in a new `app/src/problemlink.ts`. A problem
  in `studio/project.json` whose message starts `entity type "<id>"` opens
  `entities:<id>`; anything else falls back to `selectionForFile` as now. Every
  entity-type message in `core/src/validate.ts`, `behaviours.ts` and `properties.ts`
  already starts that way; a test runs real validation on broken types and checks each
  problem links to its type, so a message reworded later fails the test rather than
  the link.
- A type deleted while its page is open is handled by the fallback above.

**Project settings** keeps Project, Build and Collision classes. Where the table was,
one line: "Entity types, their properties and behaviours are on the Entities page."
with the link.

**Focus on add.** The new type's name field gets focus (a ref on `TextInput`, which
`fields.tsx` already forwards for the property editor; if not, `autoFocus` on the name
when the id equals the one just added).

Alternatives considered:
- A top item "Entities" beside World and Physics as well as the section: two ways to
  the same page in the sidebar; the section covers it.
- A typed `subject` on `Problem` instead of reading the message prefix: cleaner, but a
  change to `core` and the server's problem answers for one link. The prefix is tested
  against real messages; move to a field if a second kind of link needs it.
- Keeping the inline table and only collapsing it: does not give the type room, or a
  place for its sprite and where it is used.

## Format changes

None. `entityTypes` in `studio/project.json` is unchanged; no `FORMAT_VERSION` bump.
`#project` links still open Project settings.

## Hardware cost

None: studio interface only, nothing reaches the ROM.

## Tests

- Sidebar section and activity bar (criterion 1): `app/test/selection.test.ts` —
  `selectionFromHash('#entities:sentry')` and `#entities` round-trip; `SECTIONS`
  contains `Entity types` after `Sprites`. The rows and icon checked by hand in
  `pnpm dev` and in the new screenshots.
- Row contents and counts (2): `core/test/entities.test.ts` — `typeUsage` counts per
  room, zero rooms, a type placed only in one room; row by hand.
- Header, side by side / stacked (3): by hand at 1440 and 900 px wide; screenshot.
- Placed in, opens the room (4): `typeUsage` tests; click by hand.
- Delete asks only when placed (5): `core/test/entities.test.ts` for `withoutType`
  and the question's wording helper `deleteTypeQuestion(usage)` (null when unplaced).
- Address (6): `selection.test.ts` for the hash; `pickType(types, id)` (first type for
  a missing id, none for no types) in `core/test/entities.test.ts`.
- Links from the room panel and Problems (7): `app/test/problemlink.test.ts` with real
  `validate` output for an unknown sprite, a duplicate property, an unknown behaviour
  and a bad behaviour value, each linking to `entities:<id>`; a room problem still
  links to the room. Room Type button by hand.
- Undo and notice (8): `app/test/store-group.test.ts` — with the selection on
  `entities:<id>`, an edit then undo restores the project, and a grouped property
  change blocked by a later room edit sets the notice.
- Project settings without types (9): by hand; screenshot `project-settings` retaken.
- Keyboard (10): by hand (arrow keys, Home/End, Enter, focus on add).
- Docs (11): `docs/guide/entities.md`, moved anchors, links; `docs-writer`, and
  screenshots `entities`, `entity-properties`, `entity-behaviours`,
  `entity-property-misfit` retargeted to `#entities:sentry-bot` (`project-settings`
  and `collision-*` retaken). `pnpm docs:build` (or the VitePress build) for dead links.
